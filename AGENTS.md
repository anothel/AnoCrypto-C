# AnoCrypto-C agent instructions

- Before starting, resuming, declaring a blocker, or publishing, read the full existing GitHub issue and its latest comments, check current `main` and existing work, and follow the latest applicable authorization. Until the [v3.2 transition](docs/roadmap/DEVELOPMENT_WORKFLOW.md#v32-adoption-and-activation) is verified and its effective point is recorded, follow v3.1 and reread [delivery queue #15](https://github.com/anothel/AnoCrypto-C/issues/15) and its latest comments. After activation, read the Jira ACC queue and use #15 as the historical index. The [owner-adopted v3.2 text](https://github.com/anothel/AnoCrypto-C/issues/13#issuecomment-7079496823) defines the target.
- Under [Continuous Delivery Authorization Policy v3](https://github.com/anothel/AnoCrypto-C/issues/13#issuecomment-7069225969), the Master can authorize bounded ordinary engineering work by recording `READY_FOR_IMPLEMENTATION — OWNER_STANDING_POLICY_V3` on the existing GitHub issue. Codex acts on that record or an explicit owner authorization. Report blockers on the issue and use the queue in effect. Continue independent authorized work.
- The [v3.1 amendment](https://github.com/anothel/AnoCrypto-C/issues/13#issuecomment-7074813147) permits a [safe base refresh](docs/roadmap/DEVELOPMENT_WORKFLOW.md#safe-base-refresh) only for an approved ordinary packet with explicit `SAFE_BASE_REFRESH` authorization and all six conditions satisfied. Keep the `OWNER_STANDING_POLICY_V3` marker. Fixed-base packets and reserved changes stay under their separately recorded authority.
- Use [Current / Active / Next](docs/roadmap/CURRENT_ACTIVE_NEXT.md) for product priorities and the [development workflow](docs/roadmap/DEVELOPMENT_WORKFLOW.md#agent-assisted-delivery) for roles, handoff, and evidence. Work on a dedicated branch in an isolated worktree with a separate build directory. Preserve other branches and worktrees. Link the draft PR to its issue and report checks against the reviewed revision.
- Escalate changes to cryptographic behavior, lifecycle or public contracts, validation, security policy, or release boundaries. Keep credentials, secret material, and customer data out of the repository and review evidence.
- The maintainer controls reserved scope and merge approvals. Preserve applicable independent qualified human review at the exact candidate SHA. Follow the [release authorization gate](docs/release/RELEASE_PROVENANCE_AND_SIGNING_POLICY.md#external-release-gate). External release remains `EXTERNAL_RELEASE_NOT_AUTHORIZED`.
