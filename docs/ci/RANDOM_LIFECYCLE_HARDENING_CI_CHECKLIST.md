# Random Lifecycle Hardening CI Checklist

Status: P1-21 engineering checklist.

## Default platform lanes

- Run the ordinary random lifecycle tests.
- Run `ano_crypto_random_lifecycle_stress_tests` with repeated init/generate/reseed/uninit cycles.
- Run `ano_crypto_random_platform_review` and retain its status-only output as a runner-specific artifact.
- Confirm the artifact records provider name, availability, process-marker capability, and operation statuses only.
- Do not upload generated bytes, entropy, seed material, DRBG state, private keys, tokens, or customer data.

## Dedicated hardening lane

Configure both internal test options:

```text
ANO_CRYPTO_ENABLE_ENTROPY_TEST_HOOKS=ON
ANO_CRYPTO_ENABLE_RANDOM_TEST_HOOKS=ON
```

Keep OS entropy disabled in this deterministic lane. Run:

- entropy failure-injection tests;
- random service failure/recovery tests;
- `ano_crypto_random_reseed_limit_tests`;
- random lifecycle and entropy policy checks.

The lane verifies the final allowed generate request, reseed-required output clearing, failed-reseed persistence, successful recovery, and counter-overflow resistance without logging generated material.

## Clean Release export lane

For Linux, Windows, and Apple runners:

1. configure a shared Release build with tests/examples/hooks disabled;
2. enable internal symbol hiding;
3. build `ano_crypto_exported_symbol_baseline_check`;
4. compare actual `ano_crypto_*` exports to `abi/ANOCRYPTO_C_0_EXPORTED_SYMBOLS.txt`;
5. fail on a missing, unexpected, or internal symbol.

The stored ABI-0 baseline currently contains 53 public symbol names. Changing it requires an explicit API/ABI review and a separate decision; the test must not silently rewrite it.

## Hosted result review

A configured matrix is not evidence that every hosted runner passed. Review uploaded runner artifacts and record platform-specific failures or limitations as TODO items. Do not claim hosted Windows or Apple support before those workflow results have actually completed successfully.
