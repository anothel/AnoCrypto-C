# Release Evidence Workflow

Status: P1-28 engineering draft.

## Purpose

This workflow defines local engineering evidence collection for anocrypto-c development builds. It is not official validation evidence and should be reviewed before external sharing.

## Current evidence target

```sh
cmake --build build --target ano_crypto_collect_release_evidence
```

Default output path:

```text
build/evidence/p1-28/
```

The build target captures the complete CTest run, installed-package consumer
smoke, and customer PoC smoke as separate prerequisite steps. The evidence
assembler then copies those status-only artifacts and runs the differential and
platform review executables directly. This avoids recursive CTest/build-runner
jobserver interactions while keeping the standalone script fallback available.

## Review checklist before sharing

- Confirm the source archive excludes build outputs, generated evidence bundles, local caches, and copied third-party material.
- Confirm logs do not include entropy bytes, DRBG seed material, generated random bytes, MAC output, key material, private keys, tokens, customer data, or internal deployment details.
- Confirm KAT vector provenance is recorded in `cleanroom/SOURCE_MANIFEST.md`.
- Confirm excluded categories are recorded in `cleanroom/EXCLUSION_LOG.md`.
- Confirm claims remain limited to engineering correctness and readiness preparation.
- Confirm platform provider logs include provider name/status only.
- Confirm PoC package manifests and logs do not disclose local customer/internal details before sharing.
- Confirm P1-12 scope-review notes still match the intended customer and validation-target candidate boundary.
- Confirm P1-13 SBOM/signing placeholder status and evidence manifest are accurate.
- Confirm P1-14 thread-safety support matrix and CI checklist match the current build configuration.
- Confirm the P1-15 historical reservation and P1-22 SHA-512-family implementation/KAT records are both accurate.
- Confirm the P1-16 reserved-boundary history and P1-19 implemented random-service records are both accurate.
- Confirm P1-17 entropy hook is disabled outside the dedicated failure lane and is absent from the clean PoC SDK.
- Confirm P1-17 health-test records remain engineering skeleton evidence and contain no entropy, seed, generated bytes, or DRBG state.
- Confirm P1-20 random lifecycle, reseed-limit, hosted-platform, and exported-symbol records contain status/metadata only and no provider or generated output.
- Confirm the clean Release report matches the stored 69-symbol ABI-0 baseline.
- Confirm VM snapshot/clone and suspend/resume limitations remain explicit.
