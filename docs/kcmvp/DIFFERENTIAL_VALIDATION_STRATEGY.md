# Differential Validation Strategy

Status: P1-25 engineering strategy.

## Purpose

Differential validation is an engineering check that compares AnoCrypto-C
behavior with an independently implemented public provider under reviewed use
terms. It complements public KATs and negative tests; it does not replace KAT
provenance, formal algorithm testing, side-channel review, or official
validation.

## Selected P1-23 provider

OpenSSL 3.x `libcrypto` is selected as the first test-only provider for the
implemented SHA-2/HMAC slice. The detailed provenance, license, build, logging,
and failure-triage decision is recorded in
`docs/kcmvp/OPENSSL_DIFFERENTIAL_PROVIDER_DECISION.md`.

Provider use is limited to
`tests/differential/sha2_hmac_openssl_differential_tests.c`. The product target,
installed public headers, customer PoC SDK, and examples do not link to or
include OpenSSL because of this test lane.

## Compared services through P1-25

- SHA-256, SHA-384, and SHA-512;
- HMAC-SHA-256, HMAC-SHA-384, and HMAC-SHA-512;
- AnoCrypto-C one-shot and streaming paths;
- padding and block boundaries;
- long HMAC keys;
- multi-block and one-megabyte deterministic messages;
- intentionally unaligned input and key addresses.

The corpus is generated locally from deterministic non-secret byte recipes.
No reference output is committed as a fixture. Results are compared in memory
and all temporary digest/MAC buffers are cleared before return.

## Other service areas

| Area | Current strategy | Status |
|---|---|---|
| HMAC_DRBG-SHA-256 | Public KATs and deterministic boundary tests | Active; no external differential provider selected. |
| CSP/key handles | Lifecycle, stale/exhaustion, and HMAC result comparison through public KATs | Active. |
| Entropy/provider seams | Status-only success/failure/partial-output tests | Internal only; never compare or store entropy bytes. |
| Public random service | Lifecycle, reseed, failure, process-change, and output-clearing tests | Active; generated bytes are never retained. |
| AES-CBC without padding | Implemented in P1-25 | OpenSSL 3.x EVP is used only by a test executable; FIPS 197 and SP 800-38A remain the KAT sources. |

## Allowed inputs and sources

Allowed:

- public standards and public test vectors;
- deterministic locally generated non-secret messages and keys;
- user-owned AnoCrypto materials permitted for this project;
- independent tools/libraries after license and usage review.

Not allowed:

- non-public third-party code or documents;
- customer data;
- operational keys, entropy captures, private keys, tokens, or deployment
  material;
- vectors or implementation details from unclear sources;
- copied provider function names, internal structure, constants, or test
  harness code beyond the provider's public API.

## Logging and evidence

Allowed records:

- service and API path;
- provider name/version;
- compiler/target identity;
- input/key lengths and deterministic case identifier when triaging;
- comparison count and pass/fail status.

Prohibited records:

- digest or MAC bytes;
- generated test key/message contents;
- entropy, seed, nonce material, or DRBG state;
- generated random bytes;
- private keys, tokens, customer data, or internal deployment details.

## Failure triage

A mismatch must not automatically modify implementation code or public KAT
vectors. Reproduce with the same provider/compiler, confirm the corresponding
public KAT, isolate one-shot versus streaming and length/alignment conditions,
review API return/output handling, and record the issue without output bytes.

## Remaining work

- Review actual hosted Linux 32-bit, Windows, and macOS artifacts.
- Obtain big-endian execution evidence or explicitly keep that target outside
  the supported matrix.
- Select any additional provider only through a separate provenance/license and
  product-boundary review.
