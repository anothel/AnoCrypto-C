# DRBG and Entropy Boundary Evidence Notes

Status: P1-19 engineering evidence draft.

## Purpose

This document records the separation among the explicit-entropy DRBG API, internal entropy/provider seams, and the public source-backed random service.

The records are engineering preparation artifacts. They are not official validation evidence.

## Boundary summary

| Area | P1-19 status | Evidence target |
|---|---|---|
| HMAC_DRBG-SHA-256 deterministic core | Implemented P1 slice | Public-source KAT and boundary tests. |
| Public DRBG API | Explicit entropy input | KAT, negative, and boundary tests. |
| Internal entropy adapter | Implemented internal seam | Callback/provider unit and negative tests. |
| Platform provider | Linux/Windows/Apple reviewed build branches | Status-only provider and operational-probe tests. |
| Public random service | Implemented over source-backed HMAC_DRBG-SHA-256 | Lifecycle, provider-disabled, cross-API misuse, fork/reseed, install, and PoC smoke tests. |
| Entropy failure injection | Dedicated internal test build only | Deterministic success, complete failure, partial-write failure, and reseed retry tests. |
| Raw-noise health skeleton | Internal engineering candidate, disabled by default | Unit/error-state tests and policy records. |
| Process boundary | Private source-backed process marker | Deterministic marker and POSIX fork regression tests. |

## Allowed evidence content

Allowed:

- provider branch name;
- API status name;
- test name and pass/fail result;
- byte count without byte values;
- source and binary hashes;
- compiler, target, and build options;
- package-relative file manifests.

Prohibited:

- raw provider output;
- entropy or nonce seed material;
- generated random bytes;
- DRBG key/value state;
- customer secrets, private keys, tokens, or deployment details.

## Review checklist

- Confirm `ac_random.h` documents an implemented service and its limitations.
- Confirm no new public random-service symbol was added in P1-19.
- Confirm random contexts are caller-owned opaque storage.
- Confirm explicit DRBG contexts are rejected by random generate/reseed.
- Confirm request length is bounded and failure clears valid output buffers.
- Confirm a process-marker mismatch returns `ANO_CRYPTO_ERR_DRBG_RESEED_REQUIRED` before state advancement.
- Confirm the child-process path succeeds only after reseed.
- Confirm prediction-resistance requests remain explicitly unsupported.
- Confirm the provider-disabled lane returns `NOT_IMPLEMENTED` without exposing internal callbacks.
- Confirm ordinary and PoC builds keep entropy hooks off and hide internal symbols.
- Confirm evidence and examples never print generated bytes.
