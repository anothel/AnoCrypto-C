# DRBG and Entropy Boundary Evidence Notes

Status: P1-17 engineering evidence draft.

## Purpose

This document records how the P1 DRBG and entropy seams are separated for engineering review.

P1-17 does not claim that a public random-service implementation or finalized source-specific health-test policy is complete. The evidence focus is to prove that the boundary is explicit and that sensitive material is not captured in logs or package records.

## Boundary summary

| Area | P1-17 status | Evidence target |
|---|---|---|
| HMAC_DRBG-SHA-256 deterministic core | Implemented P1 slice | KAT and boundary tests. |
| Public DRBG API | Explicit entropy input only | KAT, negative, and boundary tests. |
| Internal entropy adapter | Implemented seam | Unit tests with callback and OS-provider status branch. |
| Internal platform provider | Implemented seam where configured | Status/provider-name tests only. |
| Internal instantiate/reseed helper | Implemented seam | Unit tests comparing explicit and helper-driven paths. |
| Public random service | Reserved ABI only | Negative reserved-API test and random boundary policy check. |
| Entropy failure injection | Internal dedicated test build only | Labeled failure/partial-write test and CI lane. |
| Health-test skeleton | Internal, disabled by default | Unit/error-state tests plus entropy/health policy record. |
| Fatal health failure | Sticky module error state | DRBG zeroization and module-state negative test. |

## Evidence allowed content

Allowed:

- provider branch name such as `linux-getrandom`, `windows-bcryptgenrandom`, `apple-secrandomcopybytes`, or `unsupported`
- API status names
- pass/fail test result
- source and binary file hashes
- compiler and build option metadata
- package manifest hashes

Not allowed:

- raw entropy bytes
- nonce bytes used as seed material
- DRBG generated bytes
- DRBG key/value state
- customer secrets
- private keys
- tokens
- customer deployment details

## Review checklist

- Confirm `ac_random.h` remains marked as a reserved boundary.
- Confirm `ano_crypto_random_*` functions do not return generated bytes.
- Confirm `ano_crypto_random_generate()` zeroizes caller output on closed-fail paths.
- Confirm the public DRBG API still requires explicit entropy input.
- Confirm prediction-resistance flags are rejected until reviewed.
- Confirm package and evidence logs do not include entropy, nonce, seed material, or generated bytes.
- Confirm platform provider availability is described as engineering status only.
- Confirm ordinary and PoC builds use `ANO_CRYPTO_ENABLE_ENTROPY_TEST_HOOKS=OFF`.
- Confirm installed headers and release-style shared-library exports do not expose internal entropy/test-hook symbols.
- Confirm health-test candidate failure logs contain only test names, status, and state—not sample bytes or DRBG state.
